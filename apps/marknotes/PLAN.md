# MarkNotes 開発計画

作成日: 2026-09-12  
状態: 2026-09-13に初期実装を追加。実装範囲と検証結果は [実装記録](docs/IMPLEMENTATION.md) を参照。

## 1. 目的と前提

Markdownで素早く書き留め、タブを閉じた後も履歴・ピン・全文検索から再利用できる、ローカルのスクラップブックを作る。タイトル入力や保存場所の指定を日常操作から外す。

開発対象は `apps/marknotes/` のみ。既存エディタ `apps/md-editor/` の修正・テスト・PyInstallerビルドとは独立して進める。既存の描画・編集処理を利用するが、両アプリ間のimportや共通環境は作らない。

以下では、ユーザー指定の要件に加えて、実装に必要な初期挙動を提案として決めている。保存方式、日時の既定、タブの「古い」の定義などはこの計画の採用案であり、ユーザーが明示した仕様と区別する。

## 2. 要件と採用する初期挙動

| 要件 | 初期実装の方針 |
| --- | --- |
| タイトルバー内のタブ | アプリの1ウィンドウ内で複数ノートを扱う。従来の新規ファイル・開く・保存ボタンを除き、タブ・新規ノートの＋・…を配置する |
| Undo / Redo | タイトルバーに残し、アクティブなノートだけを操作する |
| 自動保存・アプリ管理 | AppLocalDataLocation以下にライブラリを作り、本文と管理情報をSQLiteへ自動保存する |
| 古いタブを…へまとめる | 幅が足りない時に、最後に表示してから時間が経った非アクティブタブを隠す。閉じたり削除したりしない |
| タイトルは任意 | 独立したタイトル欄を設けず、本文冒頭から表示名を導出する |
| タブを閉じても残る | 「閉じる」はタブ状態だけを変更。ノート・添付・ピン・表示モードは保持する |
| 一括でタブを閉じる | 「すべて閉じる」「ほかのタブを閉じる」を用意する |
| 閉じたタブを開く | Ctrl+Shift+Tまたはメニューから直近に閉じたタブを戻す。一括閉鎖はまとめて復元する |
| 日付ごとのノート一覧 | 「更新日」「作成日」の切替。既定は最終更新日、新しい日付から並べる |
| ピン止め | ノートの属性として保持し、サイドバーに一覧表示する |
| 過去ノートの全文検索 | 開いていないノートも含む本文検索。SQLite FTS5を使い、日本語の短い検索語も扱う |
| ノート別の表示モード | ソースのみ・プレビューのみ・両方をノートごとに保存する |
| ノート別assets | 画像と一般ファイルを、そのノートのassetsへコピーする |
| 一般ファイルの貼り付け | 本文へMarkdownリンクを挿入する。元ファイルを後で移動しても添付を利用できる |
| サイドバー | 履歴・ピン・全文検索を単一パネル内で切り替える。既定は左側への重ね表示、任意で固定表示する |

## 3. 画面・操作仕様

### 3.1 ウィンドウとタイトルバー

上から次の配置とする。

```text
[アプリアイコン][戻す][やり直す] [ノートのタブ…] [+] […] [ドラッグ領域] [最小化][最大化][閉じる]
[サイドバー切替] ノート  編集  挿入  表示  ツール                  [ソース / プレビュー / 両方]
[必要時に開くサイドバー] [アクティブノートの編集・プレビュー領域]
[保存状態などを控えめに表示するステータスバー]
```

- ファイル名を中央に重ねて表示する既存タイトルラベルは除く。OSへ渡すウィンドウタイトルには表示名とMarkNotesを設定する。
- ＋とCtrl+Tで新規ノートを作成する。従来のファイル新規ボタンをタブの新規作成へ置き換える。
- 保存・名前を付けて保存を通常のノート操作から外す。Ctrl+Sは保存ダイアログを開かず、保留中の自動保存を直ちに要求する。
- タブをつかむ操作とウィンドウの移動を分離する。最小化・最大化・復元・スナップ・端のサイズ変更を維持する。
- タブ並べ替えを可能にする。アクティブ化のたびに論理的な並び順を変更しない。
- キーボード操作: Ctrl+Wで現在タブを閉じる、Ctrl+Shift+Tで閉じたタブを開く、Ctrl+Tab / Ctrl+Shift+Tabで前後のタブへ移動する。…内のタブも移動対象に含める。
- Ctrl+Fは現在ノートの検索、Ctrl+Shift+Fはライブラリ全体の全文検索とする。
- 初期版は1ライブラリ・1ウィンドウとする。同一ライブラリへの二重起動は既存ウィンドウへ引き継ぎ、同時編集競合を作らない。

### 3.2 ノートとタブを分ける

- ノートは永続的なIDを持つ。同じノートは同時に1タブまでとし、履歴・検索から再度選んだ場合は既存タブをアクティブにする。
- タブの集合・順序・アクティブノートを再起動後に復元する。起動時に全ノートの本文・プレビューを読み込むことはしない。
- タブを閉じる際は保留中の保存を確定する。保存失敗時は閉じず、再試行または復旧コピーの保存へ進める。
- 一括閉じるは対象ノートの保存を確認してから確定する。失敗時に一部の未保存ノートを黙って閉じない。
- 全タブを閉じた後は「新しいノート」「履歴を開く」の空画面にする。閉鎖履歴があれば「閉じたタブを開く」も表示する。自動で空ノートを作り直さない。
- ＋で作った未入力ノートはタブを閉じる・終了時に破棄する。入力後に空にしたノート、空白・改行を入力したノート、ピン止め・添付のあるノートは保持する。
- ピン止めはタブ固定とは別。ピン付きノートもタブを閉じられ、…へ収められる。
- Undo/Redo履歴はノートごとに保持し、タブ切替では失わない。初期版ではタブを閉じるまでの履歴とし、再起動後のUndo復元は対象外とする。

#### 閉じたタブを開く

- Ctrl+Shift+T、「ノート」メニュー、タブバーの右クリックメニューから実行できる。タブバーの空き領域でも右クリックでき、閉鎖履歴が空なら項目を無効にする。
- 直近に閉じた操作から順に戻す。単独で閉じた場合は1タブ、「すべて閉じる」「ほかのタブを閉じる」は1グループとして1回でまとめて戻す。繰り返し実行すると、その前の閉鎖操作へ遡る。
- 復元対象同士の元の並び順を保ち、閉鎖時の位置を目安に挿入する。現在開いているタブ同士の順序は維持する。単独復元ではそのタブを選択し、一括復元では閉鎖前のアクティブタブが対象に含まれればそれを選択する。含まれなければ復元対象の先頭を選択する。
- 同じノートが既に開いている場合はそのタブを再利用し、現在の編集内容・表示状態・位置を上書きしない。再表示する本文はノートの最新保存内容とし、保存済みの表示モード・カーソル・スクロール位置を利用する。閉鎖時点の本文へ巻き戻さず、閉鎖により破棄したUndo/Redo履歴は復元しない。
- 閉鎖履歴は直近100操作を初期上限としてDBに保持し、再起動後も利用できるようにする。一括閉鎖は1操作と数える。履歴上限を超えてもノート自体は残る。…への退避とアプリ終了は閉鎖履歴へ追加しない。
- 保存成功後に、開いているタブからの除外と閉鎖履歴への登録を同じトランザクションで確定する。保存・確定に失敗したタブは閉じず、履歴にも追加しない。復元後のタブ状態の保存と履歴の消費も同時に確定し、読み込み・復元に失敗した操作は履歴に残す。一括復元の途中失敗も再試行でき、復元済みタブを重複させない。
- 閉じる・開き直す操作だけでノートの本文更新日時を変更しない。日付別のノート履歴と、タブを閉じた操作の履歴は別に管理する。

### 3.3 …へまとめる規則

「古い」は作成日や本文の更新日ではなく、タブを最後に表示した日時を指す。

1. タイトルバーの有効幅から、最低限読み取れるタブ幅とウィンドウ操作・ドラッグ領域を確保する。
2. 収まらない場合、非アクティブタブを最終表示が古い順に…へ収める。
3. アクティブタブは必ずタイトルバーに表示する。表示するタブ同士は元の並び順を維持する。
4. …に件数と隠れたタブの一覧を表示する。選択するとそのタブを表示し、必要なら別の古いタブを収める。
5. ウィンドウを広げると再び表示する。固定日数で閉じる・削除する処理は行わない。

### 3.4 表示名と日付

- 本文の最初の空でない行をプレーンテキスト化し、見出し・強調等の記号を外して表示名にする。長い場合は画面の幅に合わせて省略する。
- 例: `# 出張の持ち物` → タブは「出張の持ち物」。空ノートは「新しいノート」。
- 冒頭が画像だけならalt、添付リンクだけならリンク文字列を利用する。表示できる文字がない場合は「画像のノート」等の代替表示にする。
- 表示名を変更してもノートID・保存先・添付ファイル名を変更しない。
- 同名のノートを許可し、一覧の日時・本文抜粋、タブのツールチップで識別できるようにする。
- `created_at` は作成時刻、`content_updated_at` は本文や添付内容を実際に変更した時刻。閲覧・ピン・タブ切替・表示モードの変更だけで本文更新日時を進めない。
- 時刻はUTCで保存し、一覧の日付区切りは利用者のローカル時刻で表示する。
- 更新日別は「最後に更新した日」に1回だけ表示する。編集したすべての日に重複表示する活動履歴は初期仕様に含めない。作成日別へ切り替えれば当初の日付から探せる。

### 3.5 サイドバー

- メニューバーの最も左に開閉ボタンを配置する。サイドバーはタイトルバー・メニューバーの下、ノート領域の左側へ重ねて表示する。
- 内部は「履歴」「ピン」「検索」の切替。履歴には日付見出し、ノートの表示名、時刻、短い抜粋を並べる。
- 既定幅は約320pxを出発点として実画面で調整する。重ね表示では編集・プレビューの幅やスクロール位置を変更しない。
- 外側クリック、Escape、ノート選択で閉じる。日本語IME変換中のEscapeは変換操作を優先する。閉じる際は適切にフォーカスを返す。
- サイドバー上部に「固定表示」の切替を置く。ノートのピン止めと別の名称・操作にする。
- 固定時はレイアウト幅を確保し、ノート選択後も開いたままにする。固定の希望と幅はアプリ設定に保存する。
- 狭いウィンドウで3ペインの最小幅が確保できない場合は一時的に重ね表示へ戻す。ウィンドウを広げた時に固定表示へ復帰する。
- 履歴・ピン一覧は本文全件を読み込まず、ページ単位で取得する。
- ピン一覧はピンを付けた順の新しいものを上にする。手動並べ替えやフォルダ分類は初期版に含めない。

### 3.6 ノート別の表示状態

- `source / preview / split` をノートごとに保存する。新しいノートの初期値は両方表示。
- カーソル・選択・ソース/プレビューのスクロール位置・分割比率もノート単位で保持する。
- 表示モード変更で本文の更新日を変えない。再び開いた時も以前の表示モードを利用する。
- プレビューのみのノートでもUndo/Redoはそのノートを対象にする。編集・検索・貼り付け時にソースを表示する既存の補助動作を引き継ぎ、操作により変わった表示モードも保存する。

## 4. 保存方式

### 4.1 SQLiteを正本にする

本文と管理情報を同じトランザクションで保存するため、SQLiteをノートの正本にする。添付ファイルはDBへ埋め込まず、ノート別フォルダへ置く。

```text
<QStandardPaths.AppLocalDataLocation>/
└── library/
    ├── library.sqlite3             # 本文・管理情報・タブ状態・検索インデックス
    ├── library.sqlite3-wal         # SQLiteが必要に応じて管理
    ├── library.sqlite3-shm
    ├── notes/
    │   └── <note_id>/
    │       └── assets/
    │           ├── image-<id>.png
    │           └── attachment-<id>.pdf
    ├── staging/                    # 添付取り込み中の作業領域
    └── recovery/                   # 中断した処理の復旧情報
```

現環境のQtによるAppLocalDataLocationは `C:/Users/yotto/AppData/Local/MarkNotes/MarkNotes`。実装ではこのパスを固定せず、Qtから取得する。

- ノートIDはUUIDとし、日付や表示名から生成しない。assetsは実際に添付が必要になった時に作成する。
- 本文はMarkdown文字列として保持するが、ノートごとの `.md` ファイルは通常保存時に二重生成しない。
- 外へ持ち出す場合はMarkdownとassetsの書き出しを用意する。編集用の正本と書き出し先を同期させない。
- 「個別MDファイルを正本＋DBを検索用」にする案もあるが、本文・日時・ピン・インデックス間の復旧規則が増えるため今回は採用しない。将来、外部ツールからの直接編集を要件にする場合は再検討する。
- アプリのインストール場所、リポジトリ、`dist/` をノート保存先にしない。

### 4.2 論理データモデル

| データ | 主な項目・責務 |
| --- | --- |
| notes | 内部整数rowid、UUID、Markdown本文、作成日時、本文更新日時、保存revision、ピン日時 |
| note_view_state | note_id、表示モード、ソース/プレビュー位置、カーソル、選択、分割比率 |
| open_tabs / app_session | note_id、順序、最終表示日時、アクティブノート |
| closed_tab_history | 閉鎖操作ID、閉鎖日時、対象note_id群、元の順序・位置、閉鎖前のアクティブノート。一括閉鎖を1操作として保持する |
| attachments | asset_id、note_id、相対パス、元ファイル名、種類、サイズ、取り込み状態 |
| note_search_content | 正規化した検索用本文、note_id。原文から再生成できる派生データ |
| note_fts | FTS5検索インデックス。検索用本文から再構築可能 |
| schema_version | DB構造のバージョンとマイグレーション管理 |

日付・ピン・タブ順序などへ用途別の索引を付ける。UI表示だけの更新でノート本文や検索インデックスを書き直さない。

### 4.3 自動保存

初期値は「入力が約700ms止まったら保存」「連続入力中も最大約5秒ごとに確定済み本文を保存」とし、実測で調整する。

- IME変換途中の文字列を本文として確定しない。通常の編集通知で取得できる確定済み本文を扱う。
- QtのGUIスレッドで本文スナップショットを取得し、ノートIDとrevisionを付けて単一の保存ワーカーへ渡す。ワーカーからQtの文書へ直接触れない。
- 同じノートの保存要求は整理し、古い保存結果で新しい内容を上書きしない。保存完了の通知もノートID・revisionと照合する。
- 本文・本文更新日時・検索用本文・FTS更新を同じDBトランザクションで確定する。
- タブ切替・ウィンドウの非アクティブ化でも直ちに保存を要求する。切替後も保存対象のノートIDを変えない。
- タブ閉鎖・一括閉鎖・アプリ終了では最新revisionの保存完了を待つ。待機中もUIを固めず、失敗時はタブと本文を保持する。
- ステータスに「保存中」「保存済み」「保存できません」を控えめに表示する。通常時の保存ダイアログは出さない。
- 保存失敗時は再試行、復旧コピーの書き出し、終了のキャンセルを提供する。失敗を成功扱いにしない。
- 自動保存でUndoの編集単位を増やしたり、Undo履歴をリセットしたりしない。

SQLiteはWALモードと `synchronous=FULL` を初期案とする。コミット時の同期に対応した設定を使い、検索の読み取りは別接続から行う。[SQLite WALの説明](https://www.sqlite.org/wal.html)

突然の終了でも確定済みデータを復元する設計とする。ただし、まだ保存されていない直近の入力まで無条件に復元できるとはしない。保存遅延・ディスク不足・途中終了を段階1から試験する。

### 4.4 バックアップと復旧

- DBのスキーマ更新前にバックアップを作る。保存ライブラリ全体の書き出し・復元も配布前の工程に含める。
- 起動中のDBを単純コピーせず、SQLite Backup API等で整合したスナップショットを作る。バックアップはDBだけでなく、その時点で参照するassetsとmanifestを含める。[SQLite Backup API](https://www.sqlite.org/backup.html)
- DBとファイルシステムを1つの原子トランザクションとして扱えると仮定しない。添付の準備・公開・DB確定の順序と、途中状態の復旧規則を実装する。
- バックアップ中は添付の変更・整理との整合を取り、外部画像編集などでコピー中の内容が変わった場合は再確認する。復元試験で本文・添付の対応を検証する。
- 検索インデックスが壊れてもノート本文を消さず、DBの正本から再構築できるようにする。

## 5. 添付ファイル

### 5.1 貼り付け

- クリップボード画像はPNG等へ保存し、`![画像](assets/image-<id>.png)` を挿入する。
- エクスプローラでコピーした画像ファイルは元形式で取り込み、画像として挿入する。
- 画像以外のファイルはassetsへコピーし、`[議事録.pdf](assets/attachment-<id>.pdf)` のようなリンクを挿入する。表示名は元ファイル名、実際の保存名は衝突しないID付きとする。
- 複数ファイル、画像と一般ファイルの混在を扱う。フォルダの再帰取り込みは初期版の対象外とし、対応外の項目を明示する。
- ファイル名の空白・日本語・括弧・Markdown記号を正しくエスケープする。
- コピー元の読み取り失敗・ファイル消失・容量不足を扱い、未完成ファイルへのリンクを挿入しない。
- 大きなコピーはバックグラウンドで行い、ノートIDと挿入位置を記録する。途中で別タブに切り替えても別のノートへ添付しない。コピー中の対象タブ閉鎖は処理完了またはキャンセルを待つ。
- HTML→Markdown、コード・引用・表など、既存の貼り付け形式は維持する。

### 5.2 本文との整合

1. stagingへコピーし、内容の書き込みを完了する。
2. ノートのassets内の最終名へ公開する。
3. 本文への挿入を1回のUndo単位で行い、添付レコードと本文を保存する。
4. 途中終了で取り込み済み・未参照のファイルが残った場合は復旧情報から検出する。本文側に存在しない完成前リンクを残さない。

Undoでリンクを消しても、Redoできる間は実ファイルを削除しない。単に現在の本文で未参照になったという理由だけで自動削除しない。添付の整理はUndo履歴・復旧データ・バックアップへの参照も考慮する別処理とする。

### 5.3 リンクを開く・画像編集・出力

- 一般添付リンクは明示的にクリックした時にOSの既定アプリで開く。貼り付け時には自動で開かない。
- 現在のプレビューは任意のローカルファイルの起動を許可していないため、管理対象assetsへのリンクを識別する処理を追加する。ノートのassets外へ抜けるパスやリンク先のすり替えを許可しない。
- プレビューのbase_dirは当該note_idのフォルダとし、相対assetsを解決する。
- 既存の画像外部編集・個別/一括改名も新しい添付管理へ適合させる。MDファイル名を前提とする命名・保存・復旧処理は置き換える。
- 画像の内容を外部編集した場合も本文更新日時を進め、プレビューを更新する。
- HTML/PDF出力は維持する。一般添付をHTML/PDFへ自動的に埋め込むとはせず、ローカル添付への依存が残る場合は出力画面に示す。持ち出しにはMarkdown＋assetsの書き出しを利用できるようにする。

## 6. 全文検索

### 6.1 検索仕様

- 対象は全ノートのMarkdown本文。コード・数式・リンク文字列も含む。添付PDF/Office文書の内容抽出や画像OCRは初期版に含めない。
- 最初は入力文字列そのものの部分一致検索とする。ユーザー入力をFTSの演算子として直接解釈しない。AND/ORや正規表現のライブラリ検索は後から検討する。
- 本文とクエリを検索用にNFKC＋casefoldで正規化し、原文は変更しない。記号は保持する。
- 検索結果はヒットしたノートごとにまとめ、冒頭からの表示名・更新日時・ピン状態と、本文の一致箇所付近の抜粋を表示する。抜粋内の検索語をすべてハイライトし、表示名にも含まれる場合はそこもハイライトする。初期並び順は本文更新日時の新しい順とする。
- 同じノートの複数の一致は1つの結果グループにまとめる。近接した一致は同じ抜粋にまとめ、離れた一致は複数の抜粋として表示する。初期表示は最大3抜粋程度とし、ノート内の一致件数と「ほかの一致」を開く操作を用意する。
- 結果・抜粋を選択すると対象ノートを開き、ノートに保存した表示モードを保つ。補足の初期案として、開いたノート本文でも検索語をハイライトし、選んだ一致箇所へ移動する。ソースのみ・プレビューのみ・両方のいずれでも、表示中のテキストの一致を強調する。
- プレビューに出ないMarkdown記号・リンク先URLなどに一致した場合も、結果一覧の抜粋では該当箇所をハイライトする。本文側は表示可能なテキストのみ強調し、必要なら「ソースで該当箇所を見る」を選べるようにする。検索結果の選択だけでは表示モードを強制変更しない。
- ハイライトは一時的な表示であり、Markdown本文・本文更新日時・自動保存内容・Undo履歴へ加えない。検索語の変更時は更新し、検索解除時に消す。サイドバーを閉じただけでは検索状態を解除しない。
- 正規化した位置を原文のカーソル位置やハイライト範囲としてそのまま使わない。文字の対応を取り、絵文字・結合文字・全角半角を考慮する。検索結果の抜粋は原文を安全にエスケープしたうえで表示上のハイライトを付ける。
- 原文上の一致範囲と、プレビューの表示テキスト上の一致範囲は別に扱う。プレビューのハイライトは既存のソース行対応やレイアウト計測を壊さない表示処理とし、ノートID・本文revision・検索世代を照合して適用する。

### 6.2 実装案と短い日本語

SQLite FTS5のtrigramを採用する。3文字以上の検索を索引で絞り、1〜2文字は正規化済み本文への部分一致検索へ切り替える。trigramの全文クエリは3 Unicode文字未満には一致しないため、この分岐が必要になる。[FTS5 trigram仕様](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)

- 3文字以上はFTSクエリを引用・エスケープし、SQLパラメータとして渡す。必要に応じて候補に原文由来の部分一致確認を行う。
- 1〜2文字は `instr(search_text, ?)` 等で検索する。短い語を検索不能にしたり、3文字以上と同じ索引効率があるように扱ったりしない。
- 3文字以上は入力停止後約250msで検索する。1〜2文字はEnterで確定して実行し、走査の連発を防ぐ。
- 検索はGUIスレッド外で行い、クエリ世代によって古い結果を捨てる。短い語の走査も中断可能にする。
- 最初は50件単位で取得し、追加取得する。全件の本文をUIへ一括転送しない。
- FTSは検索用本文を参照するexternal-content構成を候補とし、更新・削除と索引更新を同じトランザクションで行う。サイズと更新性能は段階5で実測して確定する。
- 自動保存完了後の本文が次の検索に反映される。検索実行前には現在ノートの保存を要求し、その保存完了世代を基準に検索する。
- 起動のたびに全ノートを再索引化しない。通常は変更されたノートだけ更新し、明示的な再構築経路を別に用意する。

2026-09-12の現環境はSQLite 3.49.1で、インメモリの機能確認によりFTS5/trigramが利用できた。「日本語」「C++」はtrigram検索で一致し、「会議」「議」はtrigramで一致せず部分一致走査で一致した。配布EXEの環境でも同じ機能検出を行う。これは小さな機能確認であり、性能測定ではない。

## 7. 既存コードからの変更方針

現在の `MainWindow` は1文書、ファイル保存、画像管理、表示状態を統合している。これをノート管理と表示部品に分ける。

| 現在の箇所 | 変更方針 |
| --- | --- |
| app.py / MainWindow | アプリ全体のウィンドウ・メニュー・タブ・サイドバーを管理するシェルへ整理する |
| window_chrome.py | TitleBarへタブ領域を組み込み、中央ファイル名とファイルボタンを置き換える |
| editor.py / interactions.py | 編集部品を再利用し、アクティブなNoteSessionを操作する |
| document.py / file_actions.py | 外部MDファイルの保存前提をNotebookRepository / AutosaveServiceへ置き換える。文字コード読込等は取り込み/書き出し用途に分離する |
| display_modes.py | グローバルQSettingsの表示モードをノート単位のViewStateへ移す |
| preview.py / rendering.py | 描画を再利用。ノートID・revision・表示世代を非同期応答へ付ける |
| clipboard.py / assets.py / image_actions.py / image_rename.py | 画像だけの管理から一般添付を含むassets管理へ拡張する |
| export_dialog.py / exporting.py / export_renderer.py | 管理ノートの本文とbase_dirを受け取る形へ接続し直す |
| search.py | 現在ノート内の検索として維持。ライブラリ検索は別サービスにする |

新しい責務は `storage/`（DB・移行・添付）、`notes/`（セッション・自動保存）、`ui/`（タブ・サイドバー・ノート領域）、`search/` または名称が衝突しない `library_search/` に分ける。既存の `search.py` と同名のパッケージを同時に作らない。

- 開いているノートごとに編集用QTextDocumentとUndo履歴を持ち、表示中のエディタへ切り替える。単純なsetPlainTextによる切替でUndoを消さない。
- ハイライター、編集アクション、画像Undo追跡、検索、スクロール同期の接続先をノート切替時に確実に切り替える。
- QWebEngineViewをタブ数だけ作らず、原則としてアクティブノート用の1つを使う。初期版では非アクティブなプレビューを描画しない。
- 非同期の描画・画像コピー・保存・検索の応答が、別ノートや新しいrevisionへ反映されないよう共通の識別規則を使う。
- 再起動時はタブのメタデータを先に復元し、本文は選択時に読み込む。開いているノートのUndo履歴を捨てる自動休止は初期版では行わない。

## 9. 検証方針

既存の736件は編集部品の回帰確認に活用する。単一ファイル・単一ウィンドウを前提にするテストは新仕様に合わせて見直し、件数維持自体を目的にしない。

重点的に試す組合せ:

- 日本語IME確定直後のタブ切替・閉鎖・終了、連続入力、自動保存とUndo/Redo。
- 保存順序逆転、保存ワーカー遅延、容量不足・アクセス拒否、DBロック、アプリの途中終了。
- Aノートの画像コピー・プレビュー描画が終わる前にBノートへ切り替える操作。
- 同じ冒頭テキスト、空ノート、見出しだけ、画像だけ、長文、Unicode・絵文字。
- …への出し入れ、タブ順序、一括閉鎖、再起動、ピンした閉じたノートの再表示。
- 閉じたタブの単独・連続・一括復元、全タブ閉鎖後と再起動後の復元、元の順序・選択タブ、既存タブとの重複防止、最新本文・表示状態の保持。
- 閉鎖履歴が空の場合・100操作の上限、保存失敗時に履歴を追加しないこと、復元失敗時の再試行、…への退避とアプリ終了を閉鎖として記録しないこと。
- 作成日と更新日の違い、日付境界、閲覧だけの操作、表示モード・ピン変更。
- サイドバー重ね表示と固定、狭幅、100%/150%/200% DPI、最大化・復元・スナップ。
- 日本語1/2/3文字、英数字、全半角、引用符、記号、コード、検索中の再入力、索引再構築。
- 1ノート内の複数一致、複数ノートの結果グループ、抜粋と本文のハイライト、プレビューに出ない一致、検索解除、正規化後の範囲対応、強調だけでは保存・更新日時・Undoが変わらないこと。
- 同名添付、画像とPDF等の混在、リンク特殊文字、コピー元消失、Undo後の再起動、バックアップからの復元。
- ノートごとのsource/preview/split、カーソル・スクロール・Undo履歴の独立性。

性能目標は、まず10,000ノート・本文合計約50MiB、開いた100タブを含むデータで測る。3文字以上の検索は初回50件をおおむね300ms以内、短い語は1秒程度を目標にし、いずれもGUIスレッドを止めない。数値は未測定の目標であり、性能保証ではない。10万ノートでも増え方を確認し、必要なら短語索引や検索用データ構造を追加検討する。
